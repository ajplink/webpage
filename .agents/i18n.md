# i18n conventions

## Locales

| Code | Language | URL prefix | Notes |
| --- | --- | --- | --- |
| `pt` | Portuguese (pt-PT) | `/pt/` (also `/`) | default locale, content fallback for all others |
| `en-us` | English (US) | `/en-us/` | falls back to `pt` |
| `en-gb` | English (UK) | `/en-gb/` | falls back to `en-us`, then `pt` |

Defined in `src/config/site.ts` (`LOCALES`, `DEFAULT_LOCALE`, `HTML_LANG`,
`FALLBACKS`). Adding a locale: one entry in each of those + one folder per
collection + one column in `src/i18n/ui.ts` + one column in `src/i18n/routes.ts`.

## Content: per-locale folders (the one convention)

```
src/content/<collection>/<locale>/<slug>.md
```

- `<slug>` must be **identical across locales** — it is what links translations
  and it is the URL segment of detail pages.
- The locale is read from the **folder name**, never from frontmatter.
- A missing translation is normal: the entry falls back along `FALLBACKS` and
  the page is still generated at its locale URL (`isFallback: true` in
  `src/lib/content.ts` if the UI ever needs to say so).

### Field ownership on merge

When both a `pt` file and a translated file exist for the same slug:

- **text fields** — `title`, `summary`, `role`, `location`, `bio`, `links` —
  come from the translated file (see `TEXT_FIELDS` in `src/lib/content.ts`);
- **everything else** (dates, tags, status, leads, order, covers, flags…) comes
  from the `pt` file, so translations cannot drift structurally;
- the **body** is always the translated file's own body.

## UI strings

`src/i18n/ui.ts` — one object per key, one property per locale, looked up with
`t(locale, key)` (walks the fallback chain). Interface labels only; content
never lives there.

## URLs

`src/i18n/routes.ts` maps route keys to per-locale slugs (e.g. `about` →
`/pt/sobre/`, `/en-us/about/`). Detail pages = section prefix + shared entry
slug (`/pt/eventos/<slug>/` ↔ `/en-us/events/<slug>/`). Always build links with
`href()`/`alternates()`/`absoluteUrl()`; canonical URLs use a trailing slash.

## Dates and language tags

`formatDate()`, `formatDateRange()` in `src/i18n/index.ts` (Intl per locale);
`<html lang>` and hreflang use `HTML_LANG` (`pt-PT`, `en-US`, `en-GB`).
`x-default` always points at the `pt` version.
